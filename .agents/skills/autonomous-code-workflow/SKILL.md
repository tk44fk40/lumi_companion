# 自律的コード実装 & 品質保証ワークフロー (`autonomous-code-workflow`)

開発者（ユーザー）から機能追加・修正・リファクタリングの短文指示を受けた際、本スキルを適用して以下の **7 段階自律ワークフロー** を厳格に順次実行すること。

---

## ワークフロー手順

### Step 0: Issue ・ ブランチ ＆ タスクリスト準備
作業を開始する際、以下の準備を行うこと：
1. **GitHub Issue 作成**: タスクリスト（`- [ ] タスク名`）を含む GitHub Issue を作成（または既存Issueを参照）すること。
2. **Issue 連動ブランチ作成**: `issue-<Issue番号>/<簡潔な機能名>`（例: `issue-12/subtitle-queue`）形式のブランチを作成・チェックアウトすること。
3. **計画書 (`implementation_plan.md`) メタデータ追記**: 計画書ヘッダーに関連 Issue 番号と作業ブランチ名を明記すること。

### Step 1: インターフェース（シグネチャ・型）の優先提示と合意
いきなり内部実装コードを出力しないこと。まず以下の要素のみを含む骨組み（スタブ）を提示し、ユーザーとの型合意を得ること：
- 関数のシグネチャ（関数名、引数型、戻り値型）
- Google スタイル Docstring (サマリー行、Args, Returns, Raises)

### Step 2: TDD (テスト駆動) 単体テストの先行作成＆モジュール分割
インターフェース合意後、実装コードを書く前に以下の規約で `tests/` 内にテストを作成すること：
- **適切なモジュール分割**: テスト対象の機能単位（例: `tests/test_feature.py`）で独立したテストファイルとして分割作成すること。共通処理は `conftest.py` を活用すること。
- **AAAパターンと妥当なアサート**: 「準備 (Arrange) ➔ 実行 (Act) ➔ 検証 (Assert)」の3段構造とし、意図する戻り値・状態変化を明確に `assert` すること。トリッキーな条件分岐やループをテスト内に書かないこと。
- **テスト実行確認**: `uv run pytest` を実行し、新規テストが正しく実行されること（またはRedになること）を確認。

### Step 3: アトミック（小単位）実装
最小限の実装コードを作成すること。
`coding_rules.md` のSection 3に定める「1ファイル最大300行以下」を厳守し、肥大化が見込まれる場合は自発的にクラス/モジュール分割を提案・実行すること。

### Step 4: ローカル自動コマンド検証の実行
コードを作成・変更後、ユーザーに提示する前に自身の端末で以下のコマンドを実行し、エラー0件を実証すること：
1. `uv run ruff check --fix .`
2. `uv run ruff format .`
3. `uv run basedpyright`
4. `uv run pytest`

### Step 5: 作成コード＆テストコードの「適切さ・妥当性」に関する本質的セルフチェックの提示
コマンド検証完了後、回答末尾に以下の 6 大観点による自己点検（セルフチェック）結果を簡潔に付与すること：
1. **開発ルール (`coding_rules.md`) への完全適合性**: 全規約（デザインパターン、Docstring規約、テスト分割規範等）の遵守状況
2. **要件適合性**: 依頼された本来目的の過不足ない解決
3. **設計整合性**: DI (Strategy), Facade, Context一元管理, Producer-Consumer (非同期Queue) 構造への調和
4. **テスト妥当性と非肥大化**: テストの目的・アサートが明確であり、テストコード自体がシンプルかつ適切にモジュール分割されているか
5. **簡潔性 (KISS原則)**: 不要な過剰抽象化（Over-engineering）の排除
6. **副作用と実行パフォーマンス**: 既存コンポーネントへの非破壊性および `asyncio` イベントループ非ブロッキング

### Step 6: PR作成 ・ スカッシュマージ ＆ 計画書更新
検証通過後、マージフローを実行すること：
1. **Pull Request (PR) 作成**: 本文に **`Closes #<Issue番号>`** を明記して PR を作成（`gh pr create`）。
2. **計画書メタデータ更新**: 計画書に PR 番号および参照 URL（例: `#25 (https://...)`）を追記。
3. **スカッシュマージ実行**: メインブランチへスカッシュマージ（`gh pr merge --squash`）を実行。
