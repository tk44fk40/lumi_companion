# テストカバレッジ・モック化設計ナレッジ (Test Coverage Knowledge)

本ドキュメントは `lumi_companion` における単体テスト（pytest）のカバレッジ方針、未カバー（モック化・スキップ）を許容する明確な指針、および各モジュールの未カバー箇所の技術的根拠を一元管理するナレッジドキュメントです。

---

## 1. カバレッジ基本方針
- **ビジネスロジック・データモデル・例外処理 (異常系)**: 100% のテスト網羅を目指す。
- **外部依存・物理デバイス・通信処理・抽象スタブ**: 単体テストでは非依存・確定性を保つためモック化（未カバー）を許容し、その理由・根拠を本ドキュメントに記録・維持する。

---

## 2. 単体テストで「未カバー（モック化）にしてよい」 6 大指針

1. **サードパーティ・C/C++ ネイティブライブラリ内部の処理**
   - **具体例**: OpenCV の画像デコード・リサイズ、Faster-Whisper (CTranslate2) の C++ 音声処理、Pillow のエンコードアルゴリズム等。
   - **理由**: 実績ある外部ライブラリ自体の計算精度や内部動作はライブラリ側のテストで担保されており、アプリ側の単体テストで二重に検証する必要がないため。

2. **実際のネットワーク I/O・外部 API とのリアルタイム通信**
   - **具体例**: `httpx` や `requests` による実際の Ollama サーバー（`localhost:11434`）、Cloud API (Gemini 等) への生 HTTP リクエスト。
   - **理由**: テスト実行時に外部サーバー非起動やネット切断状態（CI環境・コンテナ内等）であっても、テストが不安定（Flaky）にならず確定的に超高速実行できるようにするため。

3. **物理デバイス・特定ハードウェア依存の処理 (Heavy I/O)**
   - **具体例**: キャプチャカード/カメラからのリアルタイム映像取得、数GBの学習モデル重みの自動ダウンロード、NVIDIA GPU/CUDA メモリ割当。
   - **理由**: CIパイプラインや GPU 非搭載端末など、開発環境を問わずどの端末でも同一のテストが即座にパスするようにするため。

4. **エントリーポイント・CLI ボイラープレートコード**
   - **具体例**: スクリプト末尾の `if __name__ == "__main__": asyncio.run(main())` や CLI 引数パース (`argparse.parse_args()`) の呼び出し自体。
   - **理由**: 実質的なロジックは `main()` やサービス関数に閉じ込められており、エントリーポイントの起動構文自体は結合テスト・手動検証で確認すれば十分なため。

5. **標準フレームワーク・ロガー自体の内部出力処理**
   - **具体例**: `logger.info("...")` や `logger.debug(...)` の内部処理。
   - **理由**: ログのフォーマット出力自体はビジネスロジックの成否に直接影響しないため。

6. **抽象基底クラス (ABC) や Protocol の抽象メソッドスタブ (`...` や `pass`)**
   - **具体例**: `Protocol` クラスや `abc.ABC` 内の抽象メソッド定義体 (`def process(self): ...` や `pass`)。
   - **理由**: 抽象クラス/Protocol はインターフェース型定義（シグネチャ）の宣言を目的としており、実処理は具象派生クラス側で実装・テストされるため、ベースクラス側のスタブ行の直接実行・カバーは不要であるため。

---

## 3. 必ずテストカバーすべき領域 (モック化禁止)

1. **独自のビジネスロジック・データ加工・分析・プロンプト構築ロジック**
2. **異常系・エラーハンドリング・例外のラップ処理 (`try-except`)**
3. **データモデルの構造変換・シリアライズ/デシリアライズ (`to_dict` / `from_dict`)**
4. **コンテキスト・設定値のバリデーションや条件分岐 (`if-else`)**

---

## 4. モジュール別未カバー（モック化）箇所と技術的根拠

### Audio モジュール (`src/lumi_companion/audio/processor.py`)
- **未カバー処理**: `WhisperModel(...)` インスタンス化、`model.transcribe()` 内部処理
- **未カバーとする根拠**:
  - `faster_whisper` (C++/CUDAバインディング) 内部の重いVAD・文字起こしロジックはライブラリ側の領域であり、アプリ単体テストでのテストは不要。
  - 数GBのモデルダウンロードや GPU (CUDA) 依存を排除し、CI/CD や軽量環境で高速動作させるため。

### Vision モジュール (`src/lumi_companion/vision/extractor.py`)
- **未カバー処理**: `cv2.VideoCapture` による動画ファイルヘッダー読込およびデコード
- **未カバーとする根拠**:
  - OpenCV (C言語バイナリ) や Pillow の画像デコード・アスペクト比リサイズ自体の動作保証はライブラリ側の領域。
  - 返却データ型（幅・高さ・Base64）の変換ロジックはモックテストで検証完了済み。

### LLM モジュール (`src/lumi_companion/llm/ollama.py`)
- **未カバー処理**: `httpx.AsyncClient` による実際の Ollama サーバー（`localhost:11434`）への生 HTTP リクエスト
- **未カバーとする根拠**:
  - 単体テスト実行時に `ollama serve` プロセスが未起動の環境（CI環境等）でも確実にテストをパスさせるため。
  - 通信エラー (`ConnectionError`) 等の例外処理およびレスポンスモデル変換はモックテストで検証完了済み。

### 抽象インターフェース (`src/lumi_companion/services/protocols.py`)
- **未カバー処理**: Protocol 型内の抽象メソッドシグネチャ体 (`...`)
- **未カバーとする根拠**: 指針 6（抽象メソッドスタブ）に該当。具象サービス側で動作検証済み。

---

## 5. 今後のコード改修・リファクタリング時のメンテナビリティ指針
- 新しいモジュール追加や外部依存の変更を行った際は、本ドキュメントの未カバー根拠を同時に更新・メンテすること。
- 新たな異常系処理を追加した場合は、対応するテストケースを `tests/` に追加し、堅牢性を維持すること。
